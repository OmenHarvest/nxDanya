# nxDanya

Конфигурация NixOS 26.05 с KDE Plasma 6, Wayland, NVIDIA, Home Manager и наборами приложений для разработки, игр и повседневной работы.

Основная системная конфигурация называется `host-pc`, пользователь — `nightsoul`.

## Требования

- Компьютер `x86_64`, загруженный в режиме UEFI. Legacy BIOS не поддерживается текущей конфигурацией GRUB.
- NixOS 26.05, установленная через стандартный установщик.
- Подключение к интернету.
- NVIDIA для текущего `modules/system/graphics.nix`. Для AMD или Intel модуль требует предварительного изменения.

Отдельная установка Git в систему не требуется: используется временная среда `nix shell`.

`hardware-configuration.nix` намеренно не хранится в проекте и генерируется отдельно на каждом компьютере.

## Установка

### 1. Стандартная установка NixOS

NixOS устанавливается через графический установщик в UEFI-режиме. Разметка дисков, EFI-раздел, сеть и первоначальный пользователь настраиваются в установщике.

После завершения установки выполняется перезагрузка в установленную NixOS, а не в Live ISO.

### 2. Терминал в установленной системе

Дальнейшие команды выполняются в терминале установленной NixOS с работающим подключением к интернету.

### 3. Временная среда с Git

```bash
nix --extra-experimental-features "nix-command flakes" shell nixpkgs#git
```

Команда загружает Git и открывает временную shell-среду с доступной командой `git`. В систему Git при этом не устанавливается.

### 4. Клонирование проекта

```bash
git clone https://github.com/OmenHarvest/nxDanya
cd nxDanya
```

### 5. Генерация hardware-конфигурации

Hardware-конфигурация создаётся на компьютере, для которого предназначена система:

```bash
bash generate-hardware-configuration.sh
```

Скрипт создаёт `hosts/host-pc/hardware-configuration.nix`.

Перед продолжением проверяются:

- UUID корневого, домашнего и EFI-разделов;
- точки монтирования `/`, `/boot`, `/home` и `/nix`;
- типы файловых систем и параметры Btrfs, если они используются;
- swap и модули ядра.

Сгенерированный файл добавляется в Git-индекс, чтобы Nix включил его в источник flake:

```bash
git add hosts/host-pc/hardware-configuration.nix
```

### 6. Настройки перед пересборкой

Основные параметры находятся в следующих файлах:

- `modules/system/base.nix` — имя ПК, часовой пояс и локали;
- `modules/system/users.nix` — имя пользователя, начальный пароль и группы;
- `modules/system/graphics.nix` — видеодрайвер NVIDIA;
- `hosts/host-pc/boot.nix` — загрузчик UEFI;
- `home/users/nightsoul.nix` — пользовательские настройки Home Manager;
- `modules/apps/` — устанавливаемые приложения.

Комментарии внутри файлов описывают основные варианты редактирования.

При изменении имени `nightsoul` оно одновременно обновляется в `modules/system/users.nix`, `home/users/nightsoul.nix` и `flake.nix`. Путь к Home Manager-файлу также должен соответствовать новому имени.

### 7. Применение конфигурации

Из корня проекта выполняется команда:

```bash
sudo nixos-rebuild switch --flake .#host-pc
```

При сообщении Nix об отключённых flakes используется вариант:

```bash
sudo NIX_CONFIG="experimental-features = nix-command flakes" \
  nixos-rebuild switch --flake .#host-pc
```

После первой успешной сборки создаётся `flake.lock`. Файл сохраняется вместе с проектом и фиксирует проверенные версии Nixpkgs и внешних флейков.

### 8. Перезагрузка

```bash
sudo systemctl reboot
```

После перезагрузки запускаются SDDM и KDE Plasma.

## Первый вход

Для входа используется пользователь `nightsoul` с начальным паролем `init`. Сразу после входа пароль меняется командой:

```bash
passwd
```

`initialPassword` применяется при создании пользователя и не заменяет уже установленный пароль при каждой пересборке.

## Повседневное использование

Все команды ниже выполняются из корня проекта.

Применение изменений и создание новой загрузочной конфигурации:

```bash
sudo nixos-rebuild switch --flake .#host-pc
```

Проверка изменений без назначения конфигурации по умолчанию при загрузке:

```bash
sudo nixos-rebuild test --flake .#host-pc
```

Сборка конфигурации с применением только после следующей перезагрузки:

```bash
sudo nixos-rebuild boot --flake .#host-pc
```

Обновление версий входов и `flake.lock`:

```bash
nix flake update
sudo nixos-rebuild switch --flake .#host-pc
```

Возврат к предыдущей системной конфигурации:

```bash
sudo nixos-rebuild switch --rollback
```

Предыдущие поколения также доступны в меню GRUB.

## Структура проекта

- `flake.nix` — входы, системная конфигурация `host-pc` и подключение Home Manager.
- `configuration.nix` — общие настройки Nixpkgs и импорты модулей.
- `hosts/host-pc/` — загрузчик и сгенерированная hardware-конфигурация.
- `modules/system/` — пользователь, сеть, графика, Docker, Flatpak и базовые настройки.
- `modules/desktop/` — KDE Plasma, SDDM, PipeWire и порталы.
- `modules/apps/` — браузеры, редакторы, разработка, игры и другие приложения.
- `home/users/nightsoul.nix` — пользовательские настройки Home Manager.
- `generate-hardware-configuration.sh` — генерация hardware-конфигурации на текущем компьютере.

## Важные особенности

- Проприетарные пакеты разрешены через `nixpkgs.config.allowUnfree`.
- Docker еженедельно удаляет неиспользуемые данные; при необходимости отключается `virtualisation.docker.autoPrune`.
- Некоторые функции Steam открывают порты в брандмауэре. Неиспользуемые функции отключаются в `modules/apps/gaming.nix`.
- Сгенерированный hardware-файл проверяется перед первой пересборкой.
- Приватные ключи, пароли и другие секреты не должны храниться в проекте: значения Nix могут попасть в общедоступное хранилище Nix.
